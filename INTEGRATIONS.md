# Подключения и работа менеджеров

## Статус
Текущая версия – статическая витрина с заказом через WhatsApp. Сообщение не считается отправленным, пока покупатель не отправит его в WhatsApp. Прямой чат с ответами на сайте, VK-уведомления, автоматический район, Posiflora, платежи и управление товарами ботом ещё не подключены.

## Онлайн-консультант и роли
Для полноценного консультанта нужен сервер и база данных. Предлагаемая схема:
- Покупатель вводит имя, телефон, вопрос и согласие. Сервер создаёт диалог с непрогнозируемым клиентским токеном.
- Владельцу создаётся отдельная учётная запись. Владелец приглашает менеджеров по одноразовым ссылкам. Роль manager видит диалоги и отвечает; owner дополнительно управляет сотрудниками и настройками.
- Сообщения привязаны к диалогу и при оформлении к заказу. Покупатель видит ответы на сайте, сотрудники – в защищённой панели.
- Сервер отправляет уведомление в разрешённую беседу/сообщество ВК. Нужны ссылка сообщества, разрешения на сообщения и серверный токен. Возможность ответа прямо из ВК зависит от согласованного бота и прав сообщества.
- Полные телефоны и адреса не отправлять в общедоступные каналы. Запросы и персональные данные не хранить в Git.
- Администратором нельзя стать через общую публичную регистрацию. Учётная запись владельца создаётся при настройке сервера; менеджеров приглашает владелец.

## Контракт для будущего backend
POST /api/conversations: {name, phone, message, consent} -> {id, clientToken}
GET /api/conversations/:id/messages: clientToken -> сообщения только этого диалога.
POST /api/conversations/:id/messages: clientToken, текст.
POST /api/orders: выбранные productId/quantity, контакт, адрес, слот, согласие. Сервер повторно проверяет цену, остаток и доступность.
GET /api/catalog -> каталог с id, name, category, price, stock, composition, description, image, preorder.
GET /api/addresses?q=... -> адреса и координаты.
POST /api/delivery/quote -> zoneId, fee или requiresManager=true.
POST /api/loyalty/lookup -> authenticated/verified phone, balance, maxRedeem, expectedEarn.
POST /api/payments -> проверенный orderId; подписанный webhook подтверждает оплату.

## Google Maps и доставка
Нужны ключи Google Maps/Places, включённые сервисы, ограничения домена и квоты. Подсказки адресов и выбор точки на карте передают координаты серверу. Зоны тарификации определяются по подтверждённым магазином границам, не по совпадению названия улицы. Чурилово-Шагол, Кременкуль, неизвестная зона всегда требуют менеджера.
Северо-запад/Парковый: 400; Центр/ЧТЗ: 450; ЧМЗ/АМЗ/Ленинский: 500.
Публичный Maps browser key ограничивается доменами и API; серверные ключи держатся только в окружении backend.

## Posiflora и оплата
Только серверные обращения. Нужны доступ к API, документация именно аккаунта магазина, идентификатор магазина и правила бонусной группы. Не выдумывать реальный баланс, списание и успешную оплату.
Баланс открывать после проверки владения телефоном; простой ввод чужого номера не должен раскрывать данные клиента.
При неизвестном клиенте создавать запись идемпотентно. При нулевом балансе скрывать списание.
Подтверждённый webhook оплаты проверяет подпись, сумму, валюту, идентификатор заказа и повторную доставку события. Затем отмечает оплату, списание и начисление в Posiflora; повторное событие не начисляет бонусы повторно.
Точный момент начисления необходимо подтвердить: в исходном документе есть оба варианта – при оплате и при выполнении. Итоговые правила задаёт Posiflora.
Оплата запрещена для товара под заказ, неизвестной цены/остатка/доставки до подтверждения менеджера.

## Бот каталога
Только разрешённые ID владельца/менеджеров, роли, журнал изменений, валидация цены и остатков, предпросмотр перед публикацией. Бот работает с каталогом через backend; не редактирует публичный GitHub токеном из браузера.
